1. Project Title

Jalaram Electric - Online Electrical Products Store

A Django-based web application for an electrical goods retail and wholesale store that provides dual-tier pricing, order management, and a shopkeeper dashboard.

2. Problem Statement

Local electrical hardware shops typically manage inventory, orders, and pricing manually using paper registers or simple spreadsheets. This leads to errors in pricing (especially when handling both retail customers and bulk contractors/electricians), delays in order processing, and difficulty in tracking inventory levels. There is no unified platform where customers can browse products, add to cart, and place orders while the shop owner manages stock and updates order statuses.

This project addresses these challenges by providing a web-based system that:

  • Maintains separate retail and wholesale pricing tiers.
  • Allows customers to register, browse, and place orders online.
  • Gives the shopkeeper a dashboard to manage products, stock levels, and order statuses.
  • Automatically tracks inventory and triggers low-stock alerts.

3. Objectives

  1. To develop a fully functional e-commerce web application using the Django Python framework.
  2. To implement Django's MVT (Model-View-Template) architecture in a real-world scenario.
  3. To demonstrate Django concepts: models, views, templates, forms, URL routing, sessions, and authentication.
  4. To provide a dual-tier pricing system - Retail for regular customers and Wholesale for registered electricians/contractors.
  5. To implement session-based cart functionality for product selection and checkout.
  6. To provide order management with support for both in-store pickup and home delivery.
  7. To build a shopkeeper dashboard for managing inventory, updating prices, and tracking order statuses.
  8. To integrate Django's built-in user authentication system for secure login, registration, and logout.

6. System Design

6.1 MVT Architecture

The project follows Django's Model-View-Template (MVT) architecture:

  • Model: Defines database schema using Python classes (ORM). Located in store/models.py.
  • View: Contains the business logic, processes requests, and returns responses. Located in store/views.py.
  • Template: HTML files that render dynamic data returned from views. Located in templates/store/.

8. Implementation Details

8.1 Models (store/models.py)

Five models are defined using Django ORM: CustomerProfile, Category, Product, Order, and OrderItem. Each model has appropriate fields, relationships (ForeignKey, OneToOneField), and helper properties (e.g., is_low_stock, subtotal).

8.2 Views (store/views.py)

The application has 12 view functions implementing all major features:

  • home() - Renders the product catalog with category filter and keyword search.
  • product_detail() - Shows a single product with the applicable price tier.
  • add_to_cart() / cart_view() / remove_from_cart() - Session-based cart management.
  • checkout() - Processes the order form, creates Order and OrderItem records, deducts stock. Requires login (@login_required).
  • order_detail() / my_orders() - Customer views for order receipt and history.
  • shopkeeper_dashboard() - Staff-only view with all orders and quick stock/price update. Uses @user_passes_test decorator.
  • update_order_status() - Staff-only POST endpoint to change order status.
  • user_register() / user_login() / user_logout() - Authentication views using Django's built-in auth.

8.3 Templates (templates/store/)

All templates extend base.html using Django's template inheritance ({% extends %} and {% block %}). Templates use:

  • Template variables: {{ variable }}
  • Template tags: {% for %}, {% if %}, {% url %}, {% csrf_token %}
  • Filters: {{ price|floatformat:2 }}
  • Django messages framework for success/error notifications

8.4 Forms (store/forms.py)

Two forms are defined:

  • RegisterForm - Extends Django's ModelForm for User. Adds custom fields: password, customer_type, phone, business_name.
  • ProductQuickUpdateForm - ModelForm for quick price/stock update from dashboard.

8.5 User Management

User management uses Django's built-in django.contrib.auth system:

  • Registration creates both a User and a linked CustomerProfile.
  • Login uses AuthenticationForm and authenticate()/login().
  • Views are protected with @login_required and @user_passes_test decorators.
  • Wholesale pricing is controlled by the customer_type in CustomerProfile.

8.6 Database Integration

SQLite3 is used as the database (default Django database). Database operations use Django ORM:

  • Model.objects.all(), .filter(), .get(), .create(), .save()
  • ORM relationships: ForeignKey, OneToOneField with on_delete=CASCADE
  • Migrations managed via python manage.py makemigrations and migrate
